# dmm2yml — конвертер карт SS13 → SS14

Переносит карты из BYOND/SS13 (`.dmm`, обычный формат и TGM) в формат карт
SS14 (`.yml`, `format: 7`).

Системы сущностей у игр разные, поэтому конвертер **никогда не догадывается**.
Всё, для чего нет правила, попадает в таблицу, а `convert` отказывается делать
карту, пока в таблице есть незаполненные строки. Решение о каждой замене
принимает человек — в том числе решение «выбросить».

Нужен только Python 3.11+ и PyYAML. Сборка проекта и сабмодуль RobustToolbox
не требуются.

## Как пользоваться

```bash
# 1. Что не сопоставлено
python3 Tools/dmm2yml/dmm2yml.py scan MetaStation.dmm -o metastation.todo.csv

# 2. Открыть CSV в Excel/LibreOffice и заполнить колонку ss14_id

# 3. Собрать карту
python3 Tools/dmm2yml/dmm2yml.py convert MetaStation.dmm \
        --table metastation.todo.csv -o metastation.yml

# 4. (необязательно) Закрепить решения для следующих карт
python3 Tools/dmm2yml/dmm2yml.py merge metastation.todo.csv
```

`scan` на станции 255×255 занимает пару секунд, `convert` — около минуты.

### Колонки таблицы

| колонка | что значит |
|---|---|
| `dmm_path` | путь SS13, ключ строки |
| `kind` | `turf` / `decal` / `entity` — определяется автоматически |
| `count` | сколько раз встречается на карте |
| `example` | координаты одного экземпляра, чтобы найти его в редакторе |
| `suggestion` | подсказка, **только** точное или префиксное совпадение по имени; пусто = уверенного варианта нет |
| `ss14_id` | **заполняете вы.** id прототипа SS14 |
| `color` | для декалей, `#RRGGBBAA` |
| `notes` | переменные, встреченные у этого пути (`dir`, `name`, …) |

В `ss14_id` можно писать:

* `WallSolid` — один прототип;
* `Grille+ReinforcedWindow` — несколько сущностей на одной клетке;
* `FloorSteel+Table` — для `turf`: тайл и стоящая на нём сущность;
* `skip` — выбросить осознанно.

Пусто оставлять нельзя: именно на пустых строках `convert` останавливается.
Каждый непустой id проверяется по `Resources/Prototypes` — опечатка или
несуществующий прототип останавливают конвертацию так же, как пустая строка.

## Словари

Постоянные правила лежат в `mapping/` в YAML: там нужна вложенность, которую
CSV не выражает (тайл и сущность на одной клетке, разные id по направлению,
цвет). CSV — только для разовой дозаполнялки.

| файл | о чём |
|---|---|
| `turfs.yml` | `/turf/...` → тайл, для стен ещё и сущность |
| `decals.yml` | `/obj/effect/turf_decal/...` и `/obj/effect/decal/...` → декали |
| `entities.yml` | `/obj/...`, `/mob/...` → прототипы |
| `ignore.yml` | пути, выбрасываемые намеренно (по умолчанию — `/area`) |
| `grid_template.yml` | компоненты map- и grid-сущности готовой карты |

Правила **наследуются вниз по дереву путей**: правило для
`/turf/open/floor/iron/dark` покрывает и `/dark/corner`, и `/dark/textured`, и
`/dark/smooth_half`. Так 350 правил закрывают около 91% атомов станции /tg/.
Точное совпадение всегда важнее унаследованного. Общих правил-заглушек вроде
`/obj: SomeEntity` в словарях нет намеренно — иначе смысл таблицы теряется.

### Направление: `dir` против `wall`

SS13 прячет ориентацию части объектов в самом пути, и означает она две разные
вещи:

* `wall: north` — объект висит на стене с севера, значит в SS14 он **смотрит на
  юг**, от неё. Так помечены светильники, воздушные сигнализации, камеры, APC,
  направленные окна.
* `dir: 1` — объект просто смотрит на север. Так помечены отдельно стоящие
  вещи вроде табуретов.

Перепутать их — значит развернуть половину карты на 180°.

## Что стоит проверить глазами после конвертации

* **Повороты угловых декалей.** Направление декали в SS13 живёт в `dir`, а в
  SS14 — в самом id (`QuarterTileOverlayGreyscale90`). Соответствие
  (`N` → база, `E` → 90, `S` → 180, `W` → 270) внутри себя непротиворечиво, но
  по спрайтам не сверялось. Если углы повёрнуты — правится в `decals.yml`
  в одном месте, и все плитки следуют за ним.
* **Окна над космосом.** В SS13 внешние окна стоят прямо на космосе; в SS14 под
  ними обычно нужен пол или решётка. Конвертер тайлы сам не дорисовывает.
* **Диагональные направления.** `dir` 5/6/9/10 сводятся к одной кардинальной
  составляющей — в SS14 диагональных поворотов у большинства сущностей нет.
* **Переменные, кроме `dir` и `name`.** Отбрасываются: `pixel_x/y`, `req_access`,
  `c_tag`, `network` и ещё около 75 других. Какие именно встретились у пути,
  видно в колонке `notes`.

## Куда класть результат

**Не в `Resources/Maps/`**, пока карта не доделана.
`Content.IntegrationTests/Tests/PostMapInitTest.cs` перечисляет через
`ContentFindFiles` *все* файлы под `/Maps/` и пытается их загрузить, так что
недоделанная карта уронит CI.

Готовая карта — обычный `format: 7`: открывается редактором карт SS14, и после
пересохранения даёт минимальный diff, потому что конвертер пишет YAML в том же
виде, в каком его пишет сам SS14.

## Тесты

```bash
python3 Tools/dmm2yml/dmm2yml.py selftest
```

Восемь проверок, каждая — на ошибку, которая уже была допущена хотя бы раз:

```
  [ok  ] parser: geometry and vars         2x4, top-down rows, dir parsed
  [ok  ] rules: exact, inherited, ignored  all four behave
  [ok  ] orientation: wall vs dir          wall inverts, dir does not
  [ok  ] chunks: cell indexing             6 probes, negative chunks, variant and rotation kept
  [ok  ] chunks: round-trip vs repo maps   994/994 byte-identical across 60 maps
  [ok  ] dictionaries: ids resolve         359 rules, every id exists
  [ok  ] conversion: fixture map           tiles, entities, rotation, decal
  [ok  ] rendering: valid map document     5 entities, uids unique
```

Что именно ловится:

* **parser** — ориентация сетки `.dmm`: строки идут сверху вниз, колонки не
  перепутаны с рядами, переменные вроде `dir = 4` разбираются.
* **rules** — точное правило, унаследованное правило (побеждает более длинный
  родитель), `ignore`, и что неизвестный путь ни во что не превращается.
* **orientation** — `wall` инвертирует направление, `dir` нет, и все четыре
  поворота совпадают с теми, что выведены по `Resources/Maps/amber.yml`.
* **chunks: cell indexing** — тайл попадает в ту клетку, куда положен (включая
  отрицательные чанки), и не теряет `variant` и `rotationMirroring`.
* **chunks: round-trip** — чанки всех карт формата 7 из `Resources/Maps`
  перекодируются побайтово одинаково.
* **dictionaries** — каждый id из `mapping/*.yml` существует в
  `Resources/Prototypes`. Это ловит переименование прототипа в апстриме.
* **conversion** — крошечная карта из `selftest.py` (2×4 клетки) превращается
  ровно в то, что расписано там же руками: тайлы, стена, поворот настенного
  светильника, решётка поверх космоса, декаль с направлением.
* **rendering** — результат грузится как YAML, `format: 7`, тайл 0 — `Space`,
  у грид-сущности есть `MapGrid` и `DecalGrid`, uid'ы не повторяются.

Проверки писались от обратного: в код по очереди вносились поломки (перевёрнутая
ось Y, транспонированный индекс чанка, выброшенный байт поворота, `wall`
вместо `dir`, отключённое наследование, переименованный прототип, turf'ы
перестали применяться первыми) — каждая обязана валить нужную проверку.
Упавшая с исключением проверка считается непройденной и печатается как `FAIL`,
а не трассировкой.

Кроме того, `convert` после записи сам декодирует чанки обратно и сверяет их с
тем, что собирался записать; отключается флагом `--no-verify`.
