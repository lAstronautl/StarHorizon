# Архитектура: чистый MCP-first vs гибрид vs детерминированный

Заметка по итогам живых тестов — чтобы решить, **то ли это, что нужно**, а не на веру.

## Что показали тесты

- **Перцепция/память/крафт/инструменты через MCP — работают** (observe, recall, where_is,
  pickup, move_to/place, activate, use_on, craft/construct, listen). Любая LLM (локальная или
  внешняя) рулит агентом через один интерфейс. ✅
- **Точное движение починено** (deadzone < arrival): агент доходит вплотную, не «мимо». ✅
- **Слух через MCP работает** (`listen` ловит речь рядом). ✅
- **Но «иди за мной» через LLM — медленно и ненадёжно.** Рассуждающая модель (Qwen3.5-9b ~26
  ток/с) тратит секунды на ход; пока думает — игрок отошёл. Это **не баг, а природа LLM-в-цикле**
  для реактивного управления.

## Ключевое ограничение железа

**8 ГБ VRAM → одновременно живёт ОДНА модель** (~6 ГБ). Значит «Сайга для речи + Qwen для
инструментов разом» **не помещается**. Любая архитектура на этом железе крутит один мозг.

## Три варианта

| | Движение | Речь `{say}` | Сложные задачи | Отзывчивость | «Чистота» для статьи |
|---|---|---|---|---|---|
| **Чистый MCP-first** | LLM (move_to/follow) | LLM (say) | LLM (tools) | низкая (LLM в цикле) | высокая, новизна |
| **Гибрид** | детерминированно (мгновенно) | LLM | LLM через MCP | высокая на движении | средняя |
| **Исходный** | детерминированно | LLM | нет | высокая | низкая (не «агентный») |

### Чистый MCP-first
- **За:** один интерфейс, переносимость (любая LLM/чел подключается — ровно цель проекта),
  читаемо/воспроизводимо для статьи, нет дублирования.
- **Против:** реактивные команды («иди за мной», «стоп») лагают — модель думает секунды;
  требует близости игрока (слух/observe); модель обязана уметь tool-calling.

### Гибрид (его и просили вернуть)
- Быстрые рефлексы (follow/stop/подойди) — **детерминированно, мгновенно**, как в исходном мозге.
  LLM — только реплика `{say}` и **сложные задачи через MCP** (крафт, «принеси конкретное»).
- **Тонкость про модель речи:** для `{say}` **Сайга реально хороша** — её для русского ролеплея
  и делали; она отдаёт чистый JSON `{say}` через `format:json`. Qwen тут даже хуже как «болтун»
  (думает, ломает JSON) — её сила в tool-calling, а не в короткой реплике. Поэтому естественный
  гибрид: **детерминированное движение + Сайга/Ollama для речи**, а Qwen подключать **на сложные
  MCP-задачи отдельно** (выгрузив Сайгу — память одна).
- **Против:** возвращается детерминированный путь → меньше «чистоты MCP-first»; на 8 ГБ нельзя
  держать speech-модель и tool-модель одновременно.

### Исходный детерминированный
- Самый быстрый и простой, но LLM только за реплику — наименее «агентный», для исследования слабее.

## Так «то ли это, что нужно»?

Зависит от **цели**:

- **Если цель —研究/статья про «MCP-first embodied agent, к которому подключают любые LLM»** —
  то **чистый MCP-first и есть вклад**, а медленный «иди за мной» — известная цена LLM-в-цикле,
  её честно описать, а не маскировать. Гибрид тут «загрязняет» новизну.
- **Если цель — играбельный, отзывчивый агент** — **гибрид правильнее**: рефлексы быстрые,
  мозг (LLM) для важного. Так и у живых существ: спинной мозг (рефлексы) + кора (раздумье).
- **Компромисс, который я бы рекомендовал:** подать в статье MCP-first как **контрибуцию**
  (переносимый интерфейс действий), а гибрид — как **оптимизацию отзывчивости** поверх него
  (реактивный слой детерминирован, делиберативный — через MCP). Тогда и новизна, и практичность.
