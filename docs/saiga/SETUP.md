# Настройка Saiga (локальный ИИ-агент + MCP-сервер) в StarHorizon

Мод уже вшит в это дерево кода (`Content.Server/_Mono/Saiga`, `Content.Client/_Mono/SaigaAgent`,
`Content.Shared/_Mono/Saiga`, прототипы в `Resources/Prototypes/_Mono/...`), `SaigaManager`
зарегистрирован в IoC. Ничего компилировать/копировать вручную не нужно — просто настроить и
запустить. Ниже — три независимых способа использования, от простого к сложному.

## 0. Общее условие — локальная модель

Нужен один запущенный **OpenAI-совместимый или Ollama-сервер** с моделью (Saiga/Gemma и т.п.).
Без него сервер просто не будет отвечать (`saiga.enabled` можно оставить включённым — при ошибке
соединения агент молчит, а не падает).

**Вариант A — Ollama:**
```bash
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable --now ollama
ollama pull hf.co/QuantFactory/saiga_gemma2_9b-GGUF:Q4_K_S   # ~5.5 ГБ
ollama ps   # PROCESSOR должен быть ~100% GPU, иначе будет медленно
```
Эндпоинт по умолчанию: `http://localhost:11434`.

**Вариант B — LM Studio (или vLLM/llama.cpp/OpenAI):**
Запусти локальный сервер (обычно порт `1234`), включи режим OpenAI-совместимого API.
Эндпоинт будет вида `http://127.0.0.1:1234/v1`.

## 1. Способ 1 — NPC с личностью (проще всего, без второго клиента)

Персонаж/pAI сам отвечает на речь рядом через модель — ничего запускать отдельно не надо, только
включить CVar'ы на сервере.

**`bin/Content.Server/server_config.toml`** (или через консоль сервера):
```toml
[saiga]
enabled     = true
api_format  = "ollama"                 # или "openai" — тогда api_url оканчивается на /v1
api_url     = "http://localhost:11434"
model       = "hf.co/QuantFactory/saiga_gemma2_9b-GGUF:Q4_K_S"
```

Дальше в игре заспавни (через admin spawn-меню) один из готовых прототипов:
- **`PersonalAISaiga`** — карманное ИИ-устройство (как обычный pAI, но отвечает нейросетью, пока
  никто не занял ghost-роль).
- **`MobSaigaTao`** — полноценный гуманоидный NPC «Цзинъи Тао» с движением на нативном HTN
  (следует за тем, кто попросил, иначе стоит).

Подойди и заговори рядом (Say) — отвечает через 1-2 секунды. Поведение/личность настраиваются
прямо в прототипе (`Resources/Prototypes/_Mono/Entities/Mobs/NPCs/saiga_ai.yml`, поле
`systemPrompt`).

## 2. Способ 2 — клиент-агент, который сам пилотит персонажа игрока

Второй (обычно headless) клиент заходит в раунд и управляет своим телом: ходит, берёт предметы,
отвечает — решения принимает та же локальная модель.

Сервер — та же секция `[saiga]`, что в способе 1, плюс убедиться, что разрешён клиентский эндпоинт
(по умолчанию разрешено):
```toml
[saiga]
enabled = true
allow_client_endpoint = true   # по умолчанию true; если false — все ИИ идут через серверный api_url
```

Запуск (три терминала из корня репозитория):
```bash
# 1. сервер
dotnet run --project Content.Server

# 2. твой обычный клиент
dotnet run --project Content.Client -- --connect --username ТвоёИмя

# 3. ИИ-клиент — headless, заходит в раунд сам
dotnet run --project Content.Client -- --headless --connect --username SaigaAI \
  --cvar saiga.agent.autostart=true \
  --cvar res.texturepreloadingenabled=false
```

Либо включить агент вручную из консоли уже подключённого клиента:
```
saiga_agent on
saiga_agent goal Веди себя как обычный член экипажа, помогай, если попросят
saiga_agent off
saiga_agent join   # если нужно зайти в раунд отдельно от включения
```

Полезные клиентские CVar'ы (`saiga.agent.*`):
| CVar | По умолчанию | Смысл |
|---|---|---|
| `saiga.agent.autostart` | `false` | headless-клиент сам заходит в раунд и включает агента |
| `saiga.agent.goal` | «веди себя как обычный член экипажа...» | цель, которая идёт в system-промпт |
| `saiga.agent.endpoint` | `http://localhost:11434` | **своя** Ollama этого игрока (децентрализованный инференс — не грузит сервер) |
| `saiga.agent.num_gpu` | `-1` | сколько слоёв модели форсить на GPU у этого игрока (-1 = автоматически) |
| `saiga.agent.interval` / `saiga.agent.range` | `4` / `8` | как часто и как далеко агент воспринимает окружение |

Подойди к ИИ-персонажу и говори в Say — работает то же самое понимание команд, что в способе 1,
плюс движение/руки (следуй, возьми, брось, убери в сумку, построй стену и т.д. — полный список в
`docs/saiga/README.md`).

## 3. Способ 3 — MCP-сервер: агентом управляет внешняя LLM (Claude, GPT, ...)

Самый гибкий вариант: игровые действия выставлены как MCP-инструменты (JSON-RPC на `/mcp`), и
двигать персонажем может любая LLM-программа по стандартному протоколу — не обязательно та же
локальная модель, что в способах 1-2.

**Включить на сервере:**
```toml
[saiga]
enabled = true   # можно даже false, если MCP используется без встроенного мозга — но agent-runner
                 # с бэкендом ollama/openai всё равно ходит в свою модель сам, напрямую, а не через saiga.enabled

[saiga.mcp]
enabled = true
token   = "поставь-сюда-длинный-случайный-секрет"   # пусто = /mcp отвечает 404 (fail-closed)
```
Сгенерировать секрет, например: `openssl rand -hex 32`.

**Важно про безопасность:** `status.bind` (порт статус-хоста движка, на нём висит `/mcp`) по
умолчанию слушает на всех интерфейсах. Для разработки лучше:
```toml
[status]
bind = "127.0.0.1:1212"
```
и подключаться через SSH-туннель, если нужен доступ снаружи. Токен — это единственная защита
эндпоинта, храни его в секрете (`saiga.mcp.token` помечен `CONFIDENTIAL` — не попадёт в логи).

**Подключить Claude Code (или любой другой MCP-клиент):**
```bash
claude mcp add --transport http saiga http://127.0.0.1:1212/mcp \
  --header "Authorization: Bearer поставь-сюда-длинный-случайный-секрет"
claude mcp list   # saiga -> connected
```

**Проверка без клиента (curl):**
```bash
curl -s http://127.0.0.1:1212/mcp \
  -H "Authorization: Bearer поставь-сюда-длинный-случайный-секрет" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```
Должен вернуться список из 21 инструмента (`observe`, `listen`, `say`, `follow`, `pickup`, `craft`,
`build`, ...). Каждый вызов инструмента требует параметр `agent` — сетевой id или имя персонажа,
который берётся из `observe`/`recipes`.

**Кто именно управляется:** любая сущность-игрок в мире (не обязательно спавнить `PersonalAISaiga`
или `MobSaigaTao` — годится обычный персонаж, если внешняя LLM должна пилотить его). Зайди в игру
своим ИИ-клиентом (как в способе 2, но `saiga.agent.autostart` не обязателен — можно просто
`saiga_agent join`, чтобы заспавниться, а решения будут приходить снаружи через MCP, не от
встроенного мозга).

**Управление через `agent-runner` (Python, без внешнего LLM-провайдера типа Claude):**
Раннер уже лежит в этом репозитории — `Tools/saiga-agent-runner/runner.py`. Он сам гоняет любую
локальную/удалённую модель как MCP-клиента (не нужен Claude Code):
```bash
cd Tools/saiga-agent-runner
python3 runner.py --mcp http://127.0.0.1:1212/mcp --token поставь-сюда-секрет \
  --backend ollama --model hf.co/QuantFactory/saiga_gemma2_9b-GGUF:Q4_K_S \
  --agent SaigaAI --goal "Веди себя как обычный член экипажа" --plan
```
(`--backend ollama` бьёт напрямую в Ollama по умолчанию на `http://localhost:11434`; для LM Studio/
vLLM используй `--backend openai --backend-url http://127.0.0.1:1234/v1`.)
Подробности всех флагов (`--listen`, `--tool-mode prompt`, бэкенд `openai` для LM Studio/vLLM) —
в `Tools/saiga-agent-runner/README.md`.

## 4. Быстрая проверка, что модель вообще отвечает

Админ-команда в консоли сервера (не требует включённого агента/NPC):
```
saiga Привет, как дела?
```
Если `saiga.enabled = true` и модель доступна — выведет ответ. Если нет — покажет ошибку с
причиной (таймаут / плохой статус-код / не смог распарсить ответ) в логе сервера (sawmill
`saiga`).

## 5. Сводка всех CVar'ов

| CVar | Область | По умолчанию | Назначение |
|---|---|---|---|
| `saiga.enabled` | сервер | `false` | общий рубильник встроенного мозга (NPC/клиент-агент) |
| `saiga.api_format` | сервер | `ollama` | `ollama` (нативный `/api/chat`) или `openai` (`/chat/completions`) |
| `saiga.api_url` | сервер | `http://localhost:11434` | адрес модели по умолчанию (для `openai` — с `/v1` на конце) |
| `saiga.model` | сервер | `saiga_gemma2_9b` (GGUF) | тег модели |
| `saiga.timeout` / `saiga.temperature` / `saiga.max_tokens` / `saiga.num_ctx` / `saiga.num_gpu` | сервер | `30` / `0.4` / `256` / `2048` / `-1` | параметры генерации |
| `saiga.allow_client_endpoint` | сервер | `true` | разрешить клиентам указывать свой инференс-эндпоинт (иначе риск SSRF на чужих серверах — выключай на публичных) |
| `saiga.metrics_path` / `saiga.transcript_path` | сервер | пусто | путь к CSV-метрикам / JSONL-логу диалогов, если нужно собирать статистику |
| `saiga.mcp.enabled` | сервер | `false` | включить `/mcp` |
| `saiga.mcp.token` | сервер | пусто | Bearer-токен; пусто = эндпоинт закрыт |
| `saiga.agent.*` | клиент | см. раздел 2 | настройки клиентского ИИ-пилота персонажа |

## Известные ограничения (из апстрима, не устранялись при портировании)

- Подбор еды через `pickup` может её «съесть» (использует клавишу Use, а не чистый pickup).
- Нет полноценного пафайндинга — только грубый обход препятствий по осям.
- Агент не видит/не использует инвентарь (руки/сумка/карманы/одежда) как отдельную сущность —
  только держит один предмет в активной руке.
